Answers · Section 07

The Data Centre Power Chain — Overview

Model answers and multiple-choice key.

Multiple Choice — Answer Key

1. What does “concurrent maintainability” mean in data centre design?
Correct answer: A — Every piece of equipment needed to support the IT load can be shut down and maintained without impacting operations

2. In an N+1 redundancy topology, what happens when one module is deliberately isolated for maintenance and no other module is already faulty?
Correct answer: A — The remaining modules absorb the total load, with margin, and the site is not left “at N” as a result

3. According to the Uptime Institute Tier classification system, what distinguishes Tier III from Tier II?
Correct answer: B — Tier III adds multiple independent distribution paths on top of Tier II’s redundant components, enabling concurrent maintainability

4. What must a specialist calculate before isolating any piece of equipment in a redundant data centre?
Correct answer: A — The residual load on the surviving equipment, to confirm it stays within the site policy threshold

5. Why is an “N+1 site with one module already faulty” effectively operating at “N”?
Correct answer: C — Because the redundant module is already consumed by the existing fault, so no further isolation can occur without exceeding capacity

Long Answer — Model Points

1. Explain the difference between N, N+1, 2N, and distributed redundant (3N/2) topologies, including the operational consequence of isolating one unit of capacity in each.

N: bare capacity with no spare — any maintenance directly risks or causes an outage. N+1: one extra module beyond what’s needed, so a single module can be isolated and the remaining modules absorb the load with margin — but if another module is already unavailable, the site has no further spare capacity. 2N: two complete, independent chains, so an entire path can be isolated while the other carries 100% of the load — provided that path genuinely has the capacity and the load is truly dual-corded across both paths. Distributed redundant (3N/2): capacity is shared across several blocks sized to absorb a block’s loss collectively, offering resilience similar to 2N at lower cost, but load redistribution on an isolation is not necessarily uniform across the survivors and must be checked against the actual cross-transfer scheme.

2. Why does the guide describe residual load calculation as “reflex no. 1 of the specialist”? Explain what could go wrong if this step were skipped.

Skipping the residual load calculation risks isolating equipment while the surviving units are already near or above their safe operating capacity, potentially causing an overload event and a genuine outage — precisely the opposite of what redundancy was designed to prevent. This is why the guide treats it as the very first thing a specialist must do before any hand-over, not an optional check.

3. Compare the Uptime Institute’s Tier III and Tier IV classifications in terms of what each guarantees and the practical cost/complexity trade-off between them.

Tier III guarantees concurrent maintainability: every component in the distribution paths can be taken offline for planned maintenance without impacting the IT load, but a genuine unplanned single-component failure may still require a manual switchover with brief downtime. Tier IV additionally guarantees fault tolerance: an unplanned failure of any single system is absorbed automatically without impact. The jump from Tier III (~99.982% availability) to Tier IV (~99.995%) represents a proportionally smaller uptime gain relative to the substantial extra capital cost of duplicating the entire power and cooling chain.

4. Explain why an N+1 site with one module already in a faulted state effectively becomes an N site, and why this matters before authorising any new isolation.

In an N+1 site, the “+1” module is the only spare capacity above what’s strictly needed. If that spare module is already faulted (e.g., on static bypass due to a rectifier fault), the site now has exactly enough capacity for the load with zero margin — functionally identical to an N topology, even though it is nominally labelled N+1. Any new isolation at this point would remove genuine, needed capacity, risking an overload on the remaining modules, which is why the guide’s red list (section 21) explicitly forbids launching an operation while redundancy is already consumed, without a formal waiver.

5. Using the guide’s redundancy topology table, explain what “load transfers are cross- linked” means for distributed redundant topologies, and why the up-to-date load transfer scheme is essential before any operation.

In a distributed redundant scheme, isolating one block does not necessarily spread its load evenly across all remaining blocks — the actual redistribution follows whatever cross-transfer wiring and control logic the system was designed with, which can send disproportionate shares of the isolated block’s load to specific surviving blocks. Without consulting the current, accurate load transfer scheme, a specialist could mistakenly assume even sharing and authorise an operation that in reality pushes one surviving block well past its safe threshold.
